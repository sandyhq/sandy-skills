# sandy-skills

Engineering standards, the `proven` OpenSpec schema, the `specproof` checker and the agent skills that go with them. Public: no company names, customer data, hosts or secrets.

## Layout

- `standards/`: the standards, one topic per file, plus `sources.md`.
- `skills/<name>/SKILL.md`: agent skills (Agent Skills format).
- `openspec/schemas/proven/`: the schema. This is its only copy; adopting repos copy it.
- `openspec/specs/`: this repo's own parts, proven by its own tests.
- `tools/specproof/`: the checker. Node 20+, no dependencies.
- `.agents/skills/openspec-*`: generated by `openspec init`; change them only through `openspec update`.

## Checks

```sh
openspec validate --all --strict
mkdir -p reports && node --test --test-reporter=spec --test-reporter=junit --test-reporter-destination=stdout --test-reporter-destination=reports/junit.xml tests/*.test.mjs tools/specproof/test/*.test.mjs
node tools/specproof/bin/specproof.mjs check --junit reports/junit.xml
```

Run all three before a commit. A test's name is the claim sentence its spec requirement states; change both together.

## Rules

- Follow `standards/repo-structure.md` here too: one fact in one place, one screen per file, no empty scaffolding.
- New behaviour starts as an OpenSpec change (`openspec/changes/<id>`) with the `proven` schema.
- Keep `specproof` free of dependencies and deterministic: same specs, report and `--today` give the same output.
