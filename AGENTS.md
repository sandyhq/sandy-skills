# sandy-skills

Engineering standards, the `proven` OpenSpec schema, the agent skills and the `sandy-skills` CLI, published as the npm package `@sandyhq/sandy-skills`. Public: no company names, customer data, hosts or secrets.

## Layout

- `standards/`: the standards, one topic per file, plus `sources.md`.
- `skills/<name>/SKILL.md`: agent skills (Agent Skills format).
- `openspec/schemas/proven/`: the schema. This is its only copy; `sandy-skills init` copies it into adopting repos.
- `openspec/specs/`: this repo's own parts, proven by its own tests.
- `bin/`, `src/`, `test/`: the CLI (init, update, check, hash, confirm) and all tests. Node 22.12+.
- `docs/`: getting started and usage, for npm, pnpm and bun.
- `scripts/smoke-install.sh`: installs the packed package into empty repos with each package manager.
- `.agents/skills/openspec-*`: generated by `openspec init`; change them only through `openspec update`.

## Checks

```sh
pnpm install
pnpm exec openspec validate --all --strict
mkdir -p reports && node --test --test-reporter=spec --test-reporter=junit --test-reporter-destination=stdout --test-reporter-destination=reports/junit.xml 'test/*.test.mjs'
node bin/sandy-skills.mjs check --junit reports/junit.xml
scripts/smoke-install.sh   # before a release
```

Run the first four before a commit. A test's name is the claim sentence its spec requirement states; change both together.

## Releasing

CI and the build run on boat VMs (`runs-on: boat`); only the publish job runs on `ubuntu-latest`, because npm trusted publishing does not accept self-hosted runners. The `npm` environment allows only `v*` tags and `main`.

1. Bump `version` in `package.json`, commit, push.
2. Tag `v<version>` and push the tag. `.github/workflows/release.yml` tests, packs and stages the tarball on npm (`npm stage publish`, OIDC, provenance). Running it by hand on `main` is a dry run.
3. A maintainer of the sandyhq npm org checks and approves it with 2FA: `npm stage list @sandyhq/sandy-skills`, `npm stage approve <stage-id>`.

First release only: npm can trust a workflow only for a package that exists. From a checkout, `npm login` and `npm stage publish --access public` create `@sandyhq/sandy-skills` and stage 0.1.0; approve it as in step 3. Then on npmjs.com, package settings, add the trusted publisher: owner `sandyhq`, repo `sandy-skills`, workflow `release.yml`, environment `npm`, staging only. Its first use must come within two days.

## Rules

- Follow `standards/repo-structure.md` here too: one fact in one place, one screen per file, no empty scaffolding.
- New behaviour starts as an OpenSpec change (`openspec/changes/<id>`) with the `proven` schema.
- Name the projects under "Concepts adopted without their tools" only in `standards/sources.md`; elsewhere describe the idea itself.
- The package's only runtime dependency is OpenSpec. `check` stays deterministic: same specs, report and `--today` give the same output.
- Everything a skill or the CLI points to is a URL or ships in the package; nothing may assume a clone of this repo.
- Publishing to npm is the owner's step; see Releasing.
